# Gruzli — статическая тестовая сборка для REG.RU Host-0

## Назначение и ограничения

Эта сборка предназначена только для демонстрации интерфейса на существующем виртуальном хостинге REG.RU. Она использует локальный demo-клиент вместо Supabase.

- Регистрация и вход имитируются в браузере; пароли не проверяются настоящим сервером.
- Заказы, профили и действия сохраняются только в `localStorage` браузера на конкретном устройстве.
- Данные не синхронизируются между посетителями или устройствами и могут быть удалены очисткой данных браузера.
- Push-уведомления отключены в интерфейсе демо-сборки.
- Не вводить реальные телефоны, адреса, ФИО, данные заказов, пароли или другую персональную/конфиденциальную информацию.
- Это не production-бета и не система регистрации реальных пользователей. Для реальных пользователей сначала нужен проверенный российский backend.

## Сборка

Используйте Node.js 22 и репозиторий Gruzli. В корне проекта выполните:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm run build:demo
```

В результате команда `npm run build:demo` создаст каталог `dist/`. Режим `demo` включает локальный demo-клиент даже в production-сборке; реальные переменные Supabase для этой сборки не нужны. Не задавайте реальные значения `VITE_SUPABASE_URL` или `VITE_SUPABASE_PUBLISHABLE_KEY` при сборке демо.

Для проверки сборки локально:

```bash
npm run preview -- --host 127.0.0.1 --port 4173
```

Откройте указанный Vite URL и проверьте, что в интерфейсе отображается метка «ДЕМО · ТЕСТОВЫЕ ДАННЫЕ».

## Размещение на REG.RU Host-0

1. Убедитесь, что домен привязан к нужному сайту в ISPmanager. Не меняйте DNS, если домен уже открывает правильный сайт.
2. Включите SSL-сертификат для домена через панель хостинга и проверьте открытие сайта по HTTPS.
3. Откройте корневой каталог сайта, указанный в ISPmanager для конкретного домена.
4. Загрузите **содержимое** каталога `dist/` в корень сайта, а не каталог `dist` целиком.
5. Убедитесь, что скрытый файл `.htaccess` тоже загружен. Некоторые FTP-клиенты по умолчанию скрывают dotfiles.
6. Проверьте главную страницу и прямое открытие URL `/job/demo-job-1`. React Router должен отдавать `index.html` для неизвестных серверу путей.
7. Откройте сайт в приватном окне и на телефоне. Убедитесь, что отображается метка демо-режима и форма входа/регистрации не требует реальных данных.
8. Выполните повторную загрузку страницы и проверьте, что PWA загружается. После выкладки обновления при необходимости удалите старый кэш сайта в браузере.

## Release gate для этой демонстрации

- [ ] CI: lint, typecheck, unit tests и production build зелёные.
- [ ] Отдельная production demo-сборка успешно создаётся.
- [ ] Playwright проходит против статической demo-сборки.
- [ ] Нет запросов из demo-сборки к доменам Supabase.
- [ ] Метка демо-режима видна, кнопка push не отображается.
- [ ] SPA-пути открываются напрямую после перезагрузки.
- [ ] HTTPS работает без предупреждений.

Не приглашайте реальных пользователей к созданию настоящих заказов до развертывания и проверки backend в российском дата-центре.
