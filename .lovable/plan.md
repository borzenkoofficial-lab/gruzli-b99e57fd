# План: расширение Telegram-бота Грузли

Бот живёт в Supabase Edge Functions (TS/Deno) и работает в той же БД, что и приложение. Заявки/чаты/уведомления уже синхронизированы триггерами — ничего из существующего ломать не будем.

Объём огромный (по сути — второе приложение в Telegram), поэтому делим на **5 этапов**. После каждого можно остановиться и пользоваться.

---

## Что уже работает (трогать не будем)
- Подписка на бота, привязка аккаунта по коду (`/start CODE`)
- Привязка каналов/групп через код
- Авто-публикация новых заявок в каналы (`notify-telegram-job`)
- Личные уведомления: новая заявка, отклик, новое сообщение, смена статуса
- Рассылки админа (`admin-broadcast-telegram`)
- Long-polling (`telegram-poll`) с cron каждую минуту

---

## Этап 1 — Главное меню и кабинеты (FSM-фундамент)
- Команда `/menu` и постоянное reply-keyboard меню
- Авто-определение роли пользователя по `telegram_subscribers.user_id` → `user_roles`
- Меню **Грузчика**: Доступные заявки · Мои работы · Баланс · Рейтинг · Настройки · Поддержка
- Меню **Диспетчера**: Создать заявку · Мои заявки · Статистика · Рассылка · Настройки · Поддержка
- Если аккаунт не привязан — кнопка «Привязать аккаунт» с инструкцией
- Новая таблица `telegram_fsm_state` для пошаговых сценариев (state + data jsonb + expires_at)
- Helper-модуль `_shared/telegram.ts` (sendMessage, editMessage, answerCallback, keyboards)

## Этап 2 — Грузчик: заявки и работа
- «Доступные заявки» — список с пагинацией, inline-кнопки **Откликнуться / Подробнее**
- Просмотр карточки заявки прямо в боте
- Отклик на заявку (создаёт `job_responses` от его user_id)
- «Мои работы» — принятые заявки, кнопки смены статуса: **В пути / Прибыл / Выполняю / Завершил** (пишет в `job_responses.worker_status`)
- «Баланс» и «Рейтинг» — из `profiles`
- «Настройки»: тихий режим ночью (22:00–08:00), отключение типов уведомлений

## Этап 3 — Диспетчер: создание заявок через FSM
- «Создать заявку» — пошаговый сценарий (тип/название → адрес → метро → дата+время → длительность → кол-во грузчиков → ставка → описание → фото → срочная? → подтверждение)
- Сохраняем как `jobs` от его имени → автоматически уйдёт в каналы и грузчикам (триггеры уже есть)
- «Шаблоны заявок» — сохранение/использование `job_templates`
- «Мои заявки» — список с фильтром по статусу, инлайн-действия: **Закрыть / Отменить / Отклики**
- «Отклики» на заявку — список откликнувшихся, кнопка **Принять** (вызывает `accept_job_response`)
- «Статистика»: заявки, выполнено, доход, топ грузчиков (за неделю/месяц)

## Этап 4 — Каналы, шаблоны публикаций, рассылки
- Команда `/channels` — список привязанных каналов, переключение активности
- Шаблоны публикации заявок в канал (формат, эмодзи, авто-хештеги по городу/типу)
- Фильтр публикаций по городам (новое поле в `telegram_user_channels.city_filter`)
- Личные рассылки диспетчера своим грузчикам (тем, кто откликался хоть раз)
- Отложенные рассылки (cron-обработчик новой таблицы `scheduled_broadcasts`)

## Этап 5 — Антиспам, reminder, экспорт
- Reminder за N часов до начала заявки (cron, новая таблица `job_reminders`)
- Тихие часы (по настройкам пользователя из этапа 2)
- Rate-limit по `chat_id` в Redis-замене на `app_settings`/in-memory-LRU edge-функции
- «Чёрный список» грузчиков для диспетчера (новая таблица `dispatcher_blocked_workers`)
- Экспорт заявок диспетчера в Excel (.xlsx через edge-функцию + Storage signed URL)
- Карта заказов: deeplink на Яндекс.Карты по адресу
- Логи действий бота для админки (`telegram_bot_logs`)

---

## Что НЕ войдёт (и почему)
- **Платное продвижение / подписки внутри бота** — нужен Telegram Stars или ЮKassa, обсудим отдельно когда дойдём
- **Мультиязычность** — UI приложения только на русском, бот тоже; добавим если выйдешь за РФ
- **Геолокация в реальном времени** — Telegram Live Location требует постоянных обновлений, имеет смысл только при активной диспетчеризации в реальном времени, обсудим в этапе 5
- **Веб админ-панель отдельно** — она уже есть в приложении (`/admin`), дублировать незачем

## Технические детали (для меня)

**Архитектура:**
```
supabase/functions/
├── telegram-poll/index.ts         (роутер: command → handler)
├── _shared/telegram/
│   ├── api.ts                     (sendMessage, editMessage, etc.)
│   ├── keyboards.ts               (билдеры reply/inline)
│   ├── fsm.ts                     (load/save/clear state)
│   ├── handlers/
│   │   ├── menu.ts
│   │   ├── worker-jobs.ts
│   │   ├── worker-status.ts
│   │   ├── dispatcher-create.ts
│   │   ├── dispatcher-jobs.ts
│   │   ├── stats.ts
│   │   └── settings.ts
│   └── i18n.ts                    (тексты)
```

**Новые таблицы:** `telegram_fsm_state`, `scheduled_broadcasts`, `job_reminders`, `dispatcher_blocked_workers`, `telegram_bot_logs`, расширение `telegram_subscribers` (notification_settings jsonb), `telegram_user_channels` (city_filter, post_template).

**callback_data формат:** `<scope>:<action>:<id>` (напр. `job:respond:abc-123`, `worker:status:abc-123:arrived`). Лимит 64 байта учтём.

**Idempotency:** для всех write-действий через callback — проверка update_id или временная блокировка по `chat_id+action`.

---

## С чего стартовать

Начну с **Этапа 1**: меню, FSM-таблица, базовые хендлеры. Это разблокирует всё остальное и сразу даст пользователям видимый эффект.

Подтвердишь — начинаю с миграции для `telegram_fsm_state` и роутера в `telegram-poll`.
