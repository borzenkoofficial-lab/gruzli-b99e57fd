## Цель

Объединить ленту диспетчера (где он создаёт заявки и видит весь список своих заявок) с Кабинетом диспетчера, чтобы вся работа происходила в одном месте. Кнопку «Создать заявку» спрятать (полностью убрать из интерфейса). Существующий список заявок перенести как есть во вкладку «Активные» внутри Кабинета.

## Что сейчас

- У диспетчера на нижней панели вкладка **«Заявки»** (`feed`) открывает `DispatcherFeedScreen` — там кнопка «Создать заявку», статистика и полный список своих заявок (активные + закрытые) с управлением ставкой, откликами, редактированием, удалением.
- Из вкладки **«Профиль»** открывается `DispatcherCabinetScreen` — там 3 вкладки: «Активные» (только заказы с принятыми грузчиками), «Аналитика», «История».
- Получается дублирование: заявки видно в одном месте, активные заказы с грузчиками — в другом.

## Что нужно

### 1. Кабинет диспетчера (`DispatcherCabinetScreen.tsx`)

Во вкладке **«Активные»** показывать **обе** секции одну под другой:

1. Сверху — **полный список заявок диспетчера** (тот же визуал и логика, что в `DispatcherFeedScreen`: карточки с бейджами «Срочно/Быстрая минималка/Активна/Закрыта», адрес, время, кол-во людей, регулировка ставки ±50 ₽, кнопки «Отклики / Редактировать / Удалить»). Заголовок секции: «Мои заявки».
2. Ниже — **текущий блок «Активные заказы»** (заявки с принятыми грузчиками, раскрывающиеся карточки с грузчиками, статусами, отзывами, кнопками «Завершить», SOS и т. д.). Заголовок секции: «В работе».

Логика и обработчики из `DispatcherFeedScreen` (fetch заявок, удаление, изменение ставки, редактирование через `EditJobModal`, переход к откликам) переезжают внутрь Кабинета. `onViewResponses` подключается к существующему пропу/механизму открытия `JobResponsesScreen`.

Кнопка **«+ Создать заявку»** в Кабинете **не показывается** вообще (по требованию пользователя — «сделай чтобы не было видно»). Создание новых заявок остаётся доступным только через существующий поток создания (например, через FAB или другие точки входа), но в самом Кабинете её нет. Баннер `PushNotificationBanner` оставляем сверху списка.

Верхний блок «Quick Stats Banner» (Активных / За неделю / За месяц), ссылка «Сообщество диспетчеров» и Quick actions (Шаблоны / Топ / Цели / Отчёт) — остаются как сейчас.

### 2. Навигация (`Index.tsx` + `BottomNav.tsx` + `DesktopSidebar.tsx`)

Так как лента и кабинет теперь — одно и то же, вкладка «Заявки» в нижней панели диспетчера должна вести **прямо в Кабинет диспетчера** вместо `DispatcherFeedScreen`.

Изменения:
- В `Index.tsx`: при `tab === "feed"` для диспетчера рендерить `DispatcherCabinetScreen` (вместо `DispatcherFeedScreen`). `DispatcherFeedScreen` больше не используется и может быть удалён из импортов (сам файл пока оставить, чтобы не ломать историю).
- Пропсы Кабинета адаптировать: `onBack` для встроенного режима — no-op (стрелки «назад» не показываем, когда Кабинет открыт как корневая вкладка); `onViewResponses` подключаем к `setViewResponsesJob`; `onChatWithWorker`, `onViewProfile`, `onOpenCommunity` — как уже подключены.
- В `BottomNav` и `DesktopSidebar` метку диспетчерской вкладки оставить как «Заявки» (она и так подходит).
- Точку входа в Кабинет из «Профиль → Кабинет диспетчера» (`onOpenCabinet`) убрать или сделать так, чтобы она просто переключала на вкладку «Заявки» (так как Кабинет теперь там).

### 3. Скролл и отступы

Убедиться, что у вкладки `feed` (теперь Кабинет) работает PullToRefresh: `feedRefreshRef` пробросить в Кабинет, чтобы pull-to-refresh обновлял оба списка (заявки + активные заказы). Сохранить нижний отступ под bottom-nav (Кабинет уже использует `pb-8` + `overflow-y-auto`, проверим что хватает).

- `src/pages/Index.tsx` — заменить рендер `DispatcherFeedScreen` на `DispatcherCabinetScreen` для `tab === "feed"` у диспетчеров (и в мобильной, и в десктопной ветке); прокинуть `onViewResponses={setViewResponsesJob}`, `onRefreshRef={feedRefreshRef}`, `onBack={() => {}}`; в `ProfileScreen` props заменить `onOpenCabinet` на переключение на вкладку `feed` (`() => setTab("feed")`); убрать отдельный overlay `showCabinet` или оставить как алиас.
- `src/screens/DispatcherCabinetScreen.tsx` — скрыть кнопку «Назад» в шапке, если работаем как корневая вкладка (пропс `embedded?: boolean` или просто проверить `onBack`).

**Поведение:**
- Создание заявок: кнопка убрана из UI Кабинета. Если пользователь захочет вернуть её позднее — это отдельный запрос. Существующий `CreateJobScreen` остаётся, точка входа сейчас только из `DispatcherFeedScreen`, который мы перестаём использовать → создание новых заявок временно недоступно через UI. **Это совпадает с явной просьбой пользователя «кнопку создать заявки сделай чтобы не было видно».**
- Список заявок выглядит идентично текущему `DispatcherFeedScreen` (стеклянные карточки, регулировка ставки ±50 ₽, бейджи, кнопки откликов/редактирования/удаления).

## Что НЕ меняем

- Дизайн карточек заявок и активных заказов остаётся прежним.
- Аналитика и История в Кабинете не трогаем.
- Логика откликов, редактирования заявки, изменения ставки — как есть.
- Нижняя навигация по составу вкладок не меняется.
